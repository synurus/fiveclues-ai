# 게임 기획서 — 라이어게임 봇 프로젝트

작성 2026-09-14. 팀 프로젝트(Zeteo)를 개인 프로젝트로 이어가며 게임 구조를 다시 잡은 문서.
이전 기획서 v1~v4는 4인 팀·사람 다수 전제라 이 문서가 대체한다.

---

## 0. 프로젝트 핵심

**게임성 + 봇 프롬프트 엔지니어링.** 모든 설계 판단은 이 둘을 기준으로 내린다.

둘 중 하나만 만족하는 안은 채택하지 않는다. 재미있지만 봇 성능을 측정할 수 없으면
백엔드가 그냥 장식이고, 측정은 되는데 플레이가 지루하면 게임이 아니라 벤치마크다.

### 이 기준으로 이미 걸러낸 것

| 안 | 게임성 | 프롬프트 엔지니어링 | 판정 |
| --- | --- | --- | --- |
| 마피아 (원기획) | 높음 | **낮음** — 한 판에 판단이 수십 개 얽혀 어느 발언이 승패를 갈랐는지 추적 불가 | 기각 |
| 튜링테스트·심문형 | 중간 | **낮음** — "사람 같았나"는 사람이 판정해야 하고 판당 라벨이 1~2개, LLM 호출도 판당 40~50회 | 기각 |
| 라이어게임 (현재) | 중간~높음 | **높음** — 발언 하나 → 라벨 하나로 떨어진다 | **채택** |

라이어게임을 고른 진짜 이유는 구현 난이도가 아니라 **인과를 끊어낼 수 있다는 것**이다.
"이 발언이 제시어를 새게 했다"가 특정되므로 프롬프트를 고친 효과를 숫자로 확인할 수 있다.

## 1. 무엇이 바뀌었나

| | 팀 버전 | 개인 버전 |
| --- | --- | --- |
| 구성 | 사람 4 + 봇 1 | **사람 1 + 봇 다수** |
| 숨은 역할 | 라이어 축 / 봇 축 **두 개** | **하나** — 사람 = 라이어 |
| 봇의 목표 | 사람처럼 보이기 | **누출하지 않으면서 아는 척하기** |
| 학습 신호 | 사람 설문 (판당 몇 장, 사람 필요) | **판당 자동 라벨 다수** |
| 테스트 | 사람 4명 필요 | 혼자, 또는 무인 |

두 축이 하나로 합쳐진 게 이번 개편의 핵심이다. 사람이 무조건 라이어이므로
"봇이 라이어를 찾는 것 = 봇이 사람을 찾는 것"이 되고, 룰 설명이 한 줄로 끝난다.

---

## 2. 두 개의 모드

같은 엔진을 쓰고, **자리 하나에 사람이 앉느냐 마느냐만 다르다.**

| | 관전 모드 | 잠입 모드 |
| --- | --- | --- |
| 용도 | **데이터 수집 · 자동화 (내부 도구)** | **배포용 (플레이어가 하는 게임)** |
| 사람 | 방 밖. 참여 안 함 | 방 안. 라이어 역할 |
| 라이어 | 봇 하나에게 제시어를 안 준다 (심어진 라이어) | 사람이 곧 라이어 |
| 무인 실행 | 가능 — 밤새 돌릴 수 있다 | 불가 |
| 왜 필요한가 | 사람 발언이 봇 문맥을 오염시키지 않아 **변수가 프롬프트 하나** | 실제 게임·시연·포트폴리오 |

관전 모드로 봇을 먼저 키우고, 그 봇을 잠입 모드에 태운다.
**순서가 중요하다** — 봇이 형편없는 상태로 잠입 모드를 만들면 재미없는 이유가
게임 설계 탓인지 봇 탓인지 구분할 수 없다.

## 3. 게임 규칙 — 잠입 모드 (배포용)

### 진행

```
1. 역할 공개     봇들은 제시어를 받는다. 나는 못 받는다 (= 라이어)
2. 힌트 1라운드   전원이 제시어에 대해 한 마디씩. 나는 아는 척해야 한다
3. 힌트 2라운드   한 마디씩 더
4. 제시어 추측    내가 제시어를 맞힌다
5. 최대 힌트 지목  내가 "가장 크게 새어나간 발언" 하나를 고른다
6. 봇 투표       봇들이 "누가 라이어인가"를 투표한다 (= 나를 찾는다)
7. 결과
```

### 승패

| | 조건 |
| --- | --- |
| 내가 이긴다 | 제시어를 맞히고 **+** 봇 투표에서 지목당하지 않는다 |
| 봇이 이긴다 | 봇 투표가 나를 지목한다 |
| 무승부 | 안 들켰지만 제시어도 못 맞혔다 |

### 조기 추측 배점

**1라운드만 보고 맞히면 고득점, 2라운드까지 보면 저득점.**

없으면 나는 8개 발언이 다 나올 때까지 아무 결정도 하지 않는다.
이 규칙 하나로 "지금 지를까, 한 번 더 볼까"라는 판단이 중간에 한 번 생기고,
힌트를 2회로 나눈 구조가 비로소 의미를 가진다.

### 플레이어의 딜레마

- **잘 맞히려면** 힌트를 오래 보고, 애매한 발언을 캐물어야 한다 → 사람 티가 난다
- **안 들키려면** 짧고 밋밋하게, 아무것도 안 하면 된다 → 제시어를 못 맞힌다

캐물을수록 들킨다. 이 긴장이 잠입 모드의 재미다.

## 4. 게임 규칙 — 관전 모드 (내부 도구)

사람은 방 밖에 있다. 진행은 같되 2·3의 발언자가 전원 봇이고, **봇 하나에게만
제시어를 주지 않는다**(심어진 라이어).

4·5(추측·지목)는 사람이 해도 되고, 무인 실행 시 건너뛴다.

### 왜 라이어를 "진짜로" 심는가

라이어가 없는데 "누가 라이어냐"고 물으면 LLM은 반드시 누군가를 찍지만,
그 표가 **무엇을 재는지 알 수 없다.** 모호했던 봇을 가리키는지, 그냥 마지막에
말한 봇이나 짧게 말한 봇을 가리키는지 구분이 안 된다 (LLM 투표는 순서·위치
편향이 강하다).

라이어를 실제로 심으면 **정답이 생긴다.** "심어진 라이어를 잡아냈는가"가
맞았다/틀렸다로 떨어지고, 그게 곧 봇의 추리 능력 점수가 된다.

덤으로 라이어를 맡은 봇은 "모르는 걸 아는 척하기"를 해야 하므로
프롬프트 엔지니어링 대상이 하나 더 생긴다. 역할을 판마다 돌려 맡기면
한 봇의 두 능력을 같이 측정할 수 있다.

### 봇에게도 누출 지목을 시킨다

봇 투표와 **별개로**, 봇에게 내가 답하는 것과 같은 질문을 던진다.

> "누구의 힌트가 제시어를 가장 많이 노출시켰나?"

```
사람의 지목  =  사람 기준 정답
봇의 지목    =  모델 판단
일치율       =  이 봇이 "누출"을 얼마나 이해하는가
```

누출을 잘 알아보는 봇은 누출이 적은 힌트도 잘 만든다. 판정 능력이 발화 능력의
대리 지표가 되므로, 발화 품질을 직접 채점하지 않고도 세대를 비교할 수 있다.

## 5. 봇 설계

### 봇의 딜레마 (양쪽에서 눌린다)

| 전략 | 결과 |
| --- | --- |
| 너무 구체적 | 제시어가 새고, "최대 힌트"로 지목당한다 |
| 너무 모호 | 제시어를 모르는 것처럼 보여 라이어로 몰린다 |

이 사이를 노리는 것이 라이어게임의 본질이고, 이제 그것이 **두 개의 측정 가능한
숫자**로 표현된다. 한쪽 압력만 있으면 봇은 곧장 퇴화한다 — 누출 페널티만 있으면
전원이 "그것은 존재합니다" 수준으로 말하고 게임이 죽는다.

### 프롬프트 세대

프롬프트 후보를 세대로 관리하고, 아래 지표로 채점해 이긴 것을 남긴다.
무료 API로는 가중치를 못 건드리므로 실제로 하는 일은 **프롬프트 세대 진화**다.
이 데이터의 가치는 그 선택을 감이 아니라 숫자로 하게 만드는 데 있다.

## 6. 측정 지표

| 지표 | 정의 | 방향 |
| --- | --- | --- |
| **누출률** | 내 발언이 "최대 힌트"로 뽑힌 비율 | 낮을수록 좋음 |
| **제시어 방어율** | 사람이 제시어를 못 맞힌 판의 비율 | 높을수록 좋음 |
| **라이어 적발률** | 심어진 라이어를 맞힌 비율 (관전 모드) | 높을수록 좋음 |
| **누출 감각 일치율** | 봇의 누출 지목이 사람 지목과 일치한 비율 | 높을수록 좋음 |
| **위장 성공률** | 라이어를 맡았을 때 안 들킨 비율 | 높을수록 좋음 |

세대별로 이 지표를 꺾은선으로 그린 것이 이 프로젝트의 대표 산출물이다.

### 표본 규칙 (이걸 안 지키면 지표가 거짓말을 한다)

LLM 출력은 확률적이라 10판으로는 누출률 31%와 24%의 차이가 의미 있는지 알 수 없다.

- **세대당 최소 판수를 강제한다** (초기값 10판, 데이터 보고 조정)
- **신뢰구간을 항상 같이 표시한다** — "12% ± 9%"처럼. 불확실성을 숨기지 않는다
- **한 세대를 여러 주제·여러 단어에 걸쳐 돌린다** — 데이터는 양보다 다양성이다

## 7. 기존 스키마와의 접점

거의 그대로 쓰인다. 컬럼 신설이 필요한 항목이 적다.

| 기존 | 새 용도 |
| --- | --- |
| `game_messages.runtime_id` | 발언 하나를 지목하기 위한 식별자 — 원래 목적 그대로 |
| `survey_responses.picked_message_runtime_id` | **"가장 봇 같았던 발언" → "가장 큰 힌트였던 발언"** 으로 의미만 변경 |
| `game_votes` (`vote_type`·`voter_label`·`target_label`) | 봇의 라이어 투표, 봇의 누출 지목 (vote_type으로 구분) |
| `players.role` · `is_bot` | 심어진 라이어 표시 |
| `games.bot_provider` · `bot_model` · `bot_commit_sha` | 세대별 성적 비교의 축 |
| `games.liar_game_result` · `bot_detected_count` · `bot_voter_total` | 승패·적발 집계 |

**신설이 필요할 것**: 세대 식별자(프롬프트 버전), 조기 추측 여부(몇 라운드에서 맞혔나).

## 9. 기술 제약

### 배포

기존 판단은 "Railway 확정, Vercel 부적합"이었으나 **구성이 바뀌어 재검토 대상**이다.

- Railway 무료는 체험 $5 / 30일 후 월 $1 크레딧이라 상시 가동 불가
- **사람이 1명이 되면 Vercel의 두 가지 장벽이 사라진다** — 한 판에 소켓이 1개뿐이라
  인스턴스 간 브로드캐스트 문제가 없고, 판 길이도 300초 안에 들어온다
- ⚠️ 다만 **라운드가 무제한으로 돈다**(`stateMachine.ts`: 동점 재투표, "살린다" 선택 시
  debate 복귀 — 주석에 "횟수 제한 없이 매번"). 새 루프에서 되돌아가는 길을 없애거나
  **라운드 상한**을 두지 않으면 가끔 판이 통째로 끊긴다
- 유휴 시 잠드는 플랫폼(Render 등)으로 가면 **재접속 복구가 필수**가 된다

### LLM

| | 판당 호출 | Groq 무료 1,000회/일 기준 |
| --- | --- | --- |
| 잠입 (봇 4) | 힌트 8 + 투표 4 + 누출지목 4 = **16회** | 약 62판 |
| 관전 (봇 5) | 힌트 10 + 투표 5 + 누출지목 5 = **20회** | 약 50판 = 세대 5개 |

- Groq 1순위 (30 RPM · 1,000회/일 · 카드 불필요 · 학습 미사용), Cerebras 대체
- **Google AI Studio는 제외** — EU/UK/EEA 밖은 프롬프트를 모델 개선에 사용한다고 명시
- `bot/set-provider.ts`의 `.bot-provider` 런타임 전환으로 한도 소진 시 무재배포 전환
- 개발 중 대량 실행은 **로컬 RTX 4090**, 배포본만 무료 API를 쓰는 쪽이 현실적
- ⚠️ `RAILWAY_GIT_COMMIT_SHA`는 `db/game.ts:51`에서 `games.bot_commit_sha`에 들어간다.
  플랫폼을 옮기면 이 값이 비어 세대 비교가 망가진다 — 플랫폼 중립 이름으로 교체할 것

| 실시간(타이머) vs 턴제 | 턴제로 가면 WebSocket 자체가 불필요해져 배포 제약이 사라진다. 대신 socket.io 코드를 걷어내야 한다 |
| 봇 마릿수 | 판 길이·호출량·학습 신호 밀도가 전부 여기에 걸린다 |
| 제시어 난이도 | 주제를 알려줄지(8개 중 1), 안 알려줄지(96개 중 1). 초기엔 주제 공개 + 추측 1회로 시작해 정답률 보고 조인다 |
| 힌트 길이 제한 | 없으면 봇이 장문으로 빠져나간다 |
| 라운드 상한 | 배포처 선택과 직결 |
| 레포 이름 | 현재 `synurus/LiarGameBot`. `-Bot` 접미사가 "봇 프로그램"으로 읽혀 게임임을 가리는 문제 |

## 12. 알려진 함정

- **봇의 지배 전략은 "모호하게 말하기"다.** 누출 페널티만 있으면 전원이 침묵에 가까워지고
  게임이 죽는다. 라이어 의심이라는 반대 압력이 반드시 같이 있어야 한다.
- **사람의 지배 전략은 "성의 없게 쓰기"다.** 제시어 묘사 의무가 이걸 막는 장치이므로
  "내용은 있으면서 기계처럼 들리게"라는 긴장을 의식적으로 지킬 것.
- **라이어 없는 라이어 투표는 무엇을 재는지 알 수 없다.** 4장 참고.
- **"매판 내가 라이어"는 반복되면 밋밋해진다.** 변화는 봇 페르소나와 마릿수에서 준다
  (룰을 안 건드리면서 매 판이 달라지는 가장 싼 방법).
- **표본이 모자라면 프롬프트가 좋아진 건지 운이 좋았던 건지 모른다.** 6장의 표본 규칙 참고.
  자가대전에서 이미 겪은 문제이고, 해법도 같다 — 양보다 다양성.
