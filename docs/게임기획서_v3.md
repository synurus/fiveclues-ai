# 다섯고개 — 기획서 v3

작성 2026-09-29. v2(2026-09-15)를 대체한다. v2는 설계 근거(왜 봇 하나·라벨 양방향·세대 진화인가)가
여전히 유효해 지우지 않고 남겨 둔다 — 이 문서는 **v2 이후 실제로 만든 것**, **게임 관점의 재검토**,
**다음 로드맵**을 담는다.

## 0. 프로젝트 핵심 (v2와 같음)

**게임성 + 봇 프롬프트 엔지니어링.** AI가 묘사 다섯 개를 내고, 사람이 제시어를 맞히고, 판이
끝나면 어떤 묘사가 결정적·무쓸모였는지가 프롬프트 개선의 신호가 된다.

## 2. 현재 한 판의 흐름

```
시작 화면   [오늘의 문제 풀기] / [자유 플레이]   □ 쉬움 모드
1라운드     묘사 5개 타이핑 → 추측 1회          (쉬움 모드면 카테고리도 보임)
  ├ 정답 → 결과 「참 잘했어요」
  └ 오답 → 2라운드: 카테고리 공개 + 묘사 5개 → 추측 1회
               ├ 정답 → 「잘했어요」   └ 오답 → 「아쉬워요」 + 정답
결과        (오늘의 문제면) 공유 · 연속 정답
            👍/👎 태그 + 한마디(선택) → 피드백 보내기
```

## 3. 게임 관점 재검토

### 3.1 핵심 루프 — 플레이어가 "결정"하는 순간이 판당 두 번뿐이다 ★

지금 한 판에서 플레이어가 고르는 건 1라운드 추측과 2라운드 추측, 두 번이다. 묘사 다섯 개는
**전부 다 나온 뒤에야** 답할 수 있어서, 그 사이엔 읽기만 한다. 타이핑 연출은 "다음 걸 보면 알 것
같다"는 긴장을 만들려던 것(v2 §3)인데, 알 것 같아도 **지금 답할 수 없으니** 긴장이 행동으로
이어지지 않는다 — 오히려 기다리는 시간이 된다.

이름이 "다섯고개"(스무고개)인데 스무고개의 핵심 재미 — **한 고개씩 넘으며 "지금 부를까, 한 고개
더 볼까"를 고르는 것** — 이 빠져 있다.

**제안 A: 고개 방식(한 개씩 공개 + 언제든 추측)**

- 묘사가 한 개씩 열린다(한 개 = 한 고개). 매 고개 뒤에 **추측하기** 또는 **다음 고개**.
- 틀린 추측은 고개 하나를 쓴다(다음 묘사가 열림). 5고개를 다 쓰면 카테고리 공개 + 6~10고개.
- 점수 = 맞힌 고개 번호(1~10, 낮을수록 잘함). 공유 그리드가 풍부해진다: `🟥⬜🟩` 대신
  `⬛⬛🟩` (3고개째 정답) — 판마다 결과가 달라 공유할 맛이 난다.
- **측정이 좋아진다(가장 큰 이점).** "몇 번째 묘사에서 맞혔나"가 그대로 **객관적인 결정성
  신호**다. 지금은 👍를 사람이 손으로 골라야 하는데(v2가 꼽은 최대 리스크 = 라벨링 피로), 고개
  방식에선 추측 기록만으로 어느 묘사가 결정적이었는지 안다. 👎와 한마디만 남기면 된다.
- 필요한 것: 묘사를 **흐릿한 것 → 구체적인 것 순서**로 내야 한다(v2 §4 "난이도 계단"이 계획만
  있고 안 만들어진 부분). 프롬프트에 순서 지시 한 줄 + 묘사 세트 재생성. LLM 호출 수는 그대로
  (1~5고개 = 지금의 1라운드, 6~10고개 = 2라운드).
- 위험: 판이 더 길어질 수 있다(고개마다 결정) — 대신 쉬운 문제는 1~2고개에서 끝난다. 사람 판
  정답률 지표도 "1라운드 정답률" → "평균 고개 수"로 바뀐다(목표 밴드 새로 잡아야 함).

### 3.2 난이도 편차

성적표(`npm run metrics`, 2026-09-28)에서 카테고리별 1라운드 정답률이 0%(과일·채소 7판)~80%(과일
5판)까지 벌어진다. 표본이 작지만 "들쭉날쭉하다"는 체감과 맞는다.

- 쉬움 모드(구현) — 가볍게 즐기려는 사람의 이탈을 막는다.
- **단어별 난이도**: 오늘의 문제는 모두 같은 묘사를 풀므로 날짜별 정답률이 곧 그 문제의 난이도다.
  쌓이면 오늘의 문제 선정 때 요일별 난이도(월요일 쉬움 → 주말 어려움 같은)를 조절할 수 있다.
- 카테고리 단위 문제(과일·채소처럼 비슷한 게 많은 카테고리)는 프롬프트보다 **제시어 풀** 쪽에서
  다루는 게 싸다 — 너무 비슷한 쌍을 한 카테고리에 두지 않기.

### 3.3 결과 화면의 "아하" 순간이 약하다

틀렸을 때 정답만 나온다. 추리 게임의 보상은 "아, 그래서 그 묘사였구나"인데 그걸 도와주는 게 없다.

**제안 B: AI가 일부러 숨긴 특징 공개** — 출제 AI는 매번 `banned`(누구나 바로 떠올리는 결정적
특징)를 먼저 적고 그걸 피해서 묘사를 쓴다. 결과 화면에 "AI는 **면·육수**를 말하지 않으려
했어요"를 보여 주면, 묘사가 왜 그렇게 돌려 말했는지가 한눈에 보인다. 이미 만들어지는 정보라 비용이
없다(세트에 `banned`만 같이 저장하면 됨). 묘사 품질 검수에도 도움이 된다(banned와 묘사가 겹치면
플레이어가 바로 알아챈다).

### 3.4 다시 올 이유

- 오늘의 문제 + 연속 정답 + 공유(구현) — 매일 오는 이유.
- **지난 오늘의 문제 다시 풀기(아카이브)** — DB 없이 `scripts/daily/*.json`으로 가능. 새 방문자가
  한 번에 여러 판을 할 거리가 되고, 문제별 정적 해설 페이지로 만들면 검색 유입(애드센스)에도 좋다.
- **내 기록(브라우저 로컬)** — 판 수, 평균 고개 수(제안 A 이후), 카테고리별 강약. 서버 없이 가능.

### 3.5 피드백 동기(라벨링 피로)

v2의 대책 1(라벨을 다음 판에 반영)은 만들지 않았다. 대신 **개선 기록 공개 페이지**(구현)로 "내
피드백이 실제로 무엇을 바꿨는지"를 보여 준다. 근본 해결은 제안 A — 👍를 자동으로 얻으면 사람에게
묻는 건 👎와 한마디뿐이다.

### 3.6 공정성 — 정답 판정

오늘의 문제는 모두가 같은 단어를 풀어서, 동의어가 빠져 억울하게 틀리면 불만이 크게 번진다
(공유 결과에 🟥가 남는다). 오늘의 문제로 뽑힌 단어의 `accept`(동의어)를 일정에 올리기 전에 한 번
검토하는 절차가 필요하다 — 일정이 7일 앞까지 미리 채워지니 시간은 있다.

### 3.7 치팅과 순위표

묘사 세트·오늘의 문제 일정이 공개 저장소에 있어 정답을 찾아볼 수 있다. **순위표를 만들지 않는
한** 피해는 자기 결과뿐이라 감수한다. 순위표는 만들지 않는다(원칙) — 만들 거면 세트를 비공개
저장소로 옮기는 것부터.

### 3.8 영어판

풀 474개, 자가개선 대상 아님, 영어 피드백은 사람이 남긴 것뿐. 오늘의 문제는 영어도 나온다. 사용자
데이터가 쌓이기 전엔 한국어판 개선을 사람이 옮기는 지금 방식을 유지한다.

## 5. 세대 운영 — 자가개선 속도를 늦춘다 ★

v2 §6은 "세대당 최소 20판, 그 동안 프롬프트 고정"이었다. 지금은 매일 PR이 열리고, 머지하면 그날
바로 새 세대다. 문제가 두 겹이다:

1. **측정이 안 된다** — 세대당 사람 판이 한 자릿수라 신뢰구간이 수십 %p다. 좋아졌는지 알 수 없다.
2. **묘사 세트가 따라오지 못한다** — 세트를 새 세대로 다 바꾸는 데 약 10일(하루 64단어)이 걸린다.
   매일 머지하면 게임 대부분이 늘 옛 세대 세트로 돈다.

→ **머지 기준을 정한다:** 지금 세대로 쌓인 판이 사람+AI 합쳐 30판 이상이고, 오늘의 문제 사람
판이 한 주 이상 쌓였을 때만 다음 자가개선 PR을 머지한다(대략 주 1회). PR은 지금처럼 매일 열려도
된다 — 여러 날의 PR 중 가장 근거가 좋은 것을 고르면 된다. PR 본문의 세대별 성적표가 그 판단 근거다.

## 8. 함정

- **세대를 너무 자주 바꾸면 아무것도 측정하지 못한다**(§5).
- **AI 판 성적을 사람 성적처럼 읽는다** — 추측 모델에 따라 17%와 100%가 같은 세대에서 나온다.
- **피드백을 보낸 판만 기록된다** — 사람 판 정답률은 "피드백을 남기는 사람"의 정답률이다.
- **오늘의 문제의 억울한 오답은 공유를 타고 번진다**(§3.6).
- **공개 저장소의 정답** — 순위표를 만드는 순간 문제가 된다(§3.7).
- **무료 모델 한도** — 3.8-flash 하루 20회를 자가개선과 세트 생성이 나눠 쓴다(CLAUDE.md).
